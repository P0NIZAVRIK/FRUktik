## 1. НАЗНАЧЕНИЕ ПРОГРАММЫ

### 1.1 Общие сведения

Мобильное приложение «FRUktik» — это программный продукт, реализованный на платформе Flutter, предназначенный для автоматического учёта питания пользователей с применением мультимодальных языковых моделей (LLM Vision). Приложение позволяет пользователям фотографировать блюда и мгновенно получать информацию о калорийности и нутриентном составе (КБЖУ).

С точки зрения оператора, система «FRUktik» представляет собой многоуровневый программный комплекс, включающий:

- **Клиентское приложение** — мобильное приложение на Flutter (Android / iOS);
- **Сервер автоматизации n8n** — обрабатывает входящие вебхуки от мобильного клиента, взаимодействует с AI-API (OpenRouter / Mistral Vision) и возвращает результаты анализа;
- **База данных Supabase (PostgreSQL)** — облачное хранилище профилей пользователей, записей дневника питания и справочника продуктов.

### 1.2 Функции, выполняемые программой

Программный комплекс выполняет следующие функции:

| № | Функция | Исполнитель |
|---|---------|-------------|
| 1 | Регистрация и аутентификация пользователей | Supabase Auth |
| 2 | Захват и передача изображения блюда | Мобильный клиент |
| 3 | Сжатие изображения для передачи по сети | N8nService (клиент) |
| 4 | Маршрутизация запроса к AI-модели | Сервер n8n |
| 5 | Семантический анализ фото, определение КБЖУ | Mistral Large Vision (через OpenRouter API) |
| 6 | Хранение записей дневника питания | Supabase (PostgreSQL) |
| 7 | Отображение нутриентной статистики пользователю | Мобильный клиент |
| 8 | Синхронизация данных при восстановлении связи | DatabaseService (клиент) |

## 3. ВЫПОЛНЕНИЕ ПРОГРАММЫ

### 3.1 Запуск серверной части (n8n)

#### 3.1.1 Начало работы — первоначальная настройка

**Шаг 1. Установка Docker**

Убедитесь, что Docker и Docker Compose установлены на сервере:

```bash
docker --version
docker compose version
```

Если Docker не установлен, следуйте официальной документации: https://docs.docker.com/engine/install/

**Шаг 2. Создание конфигурационного файла**

Создайте директорию для проекта и файл `docker-compose.yml`:

```bash
mkdir fruktik-n8n && cd fruktik-n8n
nano docker-compose.yml
```

Содержимое файла `docker-compose.yml`:

```yaml
version: '3.8'
services:
  n8n:
    image: n8nio/n8n:latest
    restart: always
    ports:
      - "5678:5678"
    environment:
      - N8N_BASIC_AUTH_ACTIVE=true
      - N8N_BASIC_AUTH_USER=admin
      - N8N_BASIC_AUTH_PASSWORD=<ВАШ_БЕЗОПАСНЫЙ_ПАРОЛЬ>
      - N8N_HOST=0.0.0.0
      - N8N_PORT=5678
      - WEBHOOK_URL=https://<ВАШ_ДОМЕН_ИЛИ_IP>:5678/
      - GENERIC_TIMEZONE=Europe/Moscow
    volumes:
      - n8n_data:/home/node/.n8n

volumes:
  n8n_data:
```

**Шаг 3. Запуск контейнера**

```bash
docker compose up -d
```

**Шаг 4. Проверка запуска**

```bash
docker compose ps
```

Контейнер должен находиться в состоянии `Up`. Для просмотра логов:

```bash
docker compose logs -f n8n
```

**Шаг 5. Открытие веб-интерфейса n8n**

Откройте в браузере: `http://<ВАШ_IP>:5678`

Войдите с использованием учётных данных, указанных в `docker-compose.yml`.

#### 3.1.2 Импорт рабочего процесса FRUktik

В корне проекта находится файл `n8n_fruktik_unified_blueprint.json`, содержащий предварительно настроенный рабочий процесс (Workflow) для обработки запросов от мобильного приложения.

**Процедура импорта:**

1. В веб-интерфейсе n8n нажмите кнопку **«+ New Workflow»** (или значок «+» в левом меню).
2. В открывшемся меню выберите **«Import from File»**.
3. Загрузите файл `n8n_fruktik_unified_blueprint.json`.
4. После импорта рабочий процесс появится в редакторе.
5. Настройте узел **«HTTP Request»** (запрос к OpenRouter): укажите API-ключ OpenRouter в заголовке `Authorization: Bearer <ВАШ_API_КЛЮЧ>`.
6. Нажмите **«Save»** и затем **«Activate»** (переключатель в правом верхнем углу).

После активации система начнёт обрабатывать входящие вебхуки по адресу:

```
https://<ВАШ_ДОМЕН>:5678/webhook/<ИДЕНТИФИКАТОР_ВЕБХУКА>
```

**Внимание:** Скопируйте URL вебхука — он потребуется для настройки мобильного приложения.

#### 3.1.3 Настройка Supabase

**Шаг 1.** Войдите в панель управления Supabase (https://app.supabase.com).

**Шаг 2.** Создайте новый проект. Запишите:
- **Project URL** (вида `https://xxxxxxxxxxx.supabase.co`)
- **anon/public key** (находится в разделе **Settings → API**)

**Шаг 3.** Создайте необходимые таблицы. Перейдите в **SQL Editor** и выполните следующий скрипт:

```sql
-- Таблица записей дневника питания
CREATE TABLE diary_entries (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id     UUID NOT NULL,
    date        TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    meal_name   TEXT,
    calories    NUMERIC(8,2),
    proteins    NUMERIC(8,2),
    fats        NUMERIC(8,2),
    carbs       NUMERIC(8,2),
    photo_url   TEXT,
    raw_ai_response TEXT,
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Политика безопасности: пользователь видит только свои записи
ALTER TABLE diary_entries ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users access own entries"
    ON diary_entries
    FOR ALL
    USING (auth.uid() = user_id);
```

**Шаг 4.** Настройте Supabase Auth:
- Перейдите **Authentication → Settings**.
- При необходимости настройте провайдеры входа (Email/Password — включено по умолчанию).

#### 3.1.4 Настройка конфигурационных файлов приложения

Конфигурация мобильного приложения задаётся в файлах:

- `lib/core/config/ai_config.dart` — URL вебхука n8n и ключи API
- `lib/core/config/supabase_config.dart` — учётные данные Supabase

Оператор должен передать разработчику следующие параметры для внесения в конфигурационные файлы:

| Параметр | Источник | Файл |
|---------|---------|------|
| `n8nWebhookUrl` | URL вебхука n8n после активации Workflow | `ai_config.dart` |
| `supabaseUrl` | Project URL из панели Supabase | `supabase_config.dart` |
| `supabaseAnonKey` | anon/public key из панели Supabase | `supabase_config.dart` |
| `openRouterApiKey` | API-ключ из https://openrouter.ai | `ai_config.dart` |

### 3.2 Остановка программы

#### 3.2.1 Плановая остановка серверной части

Для плановой остановки контейнера n8n выполните команду:

```bash
cd fruktik-n8n
docker compose stop
```

Данные рабочих процессов и настроек n8n сохраняются в томе Docker (`n8n_data`) и не теряются при остановке.

#### 3.2.2 Аварийная остановка

В случае необходимости принудительной остановки:

```bash
docker compose down
```

**Предупреждение:** Команда `docker compose down` останавливает контейнер. Данные сохраняются благодаря тому, что том (`n8n_data`) не удаляется. Для **полного** удаления данных необходимо явно указать флаг `-v`:

```bash
docker compose down -v   # ВНИМАНИЕ: удаляет все данные n8n!
```

### 3.3 Режимы работы системы и контроль функционирования

#### 3.3.1 Штатный режим

В штатном режиме взаимодействие компонентов системы осуществляется по следующей схеме:

```
Пользователь (фото)
      │
      ▼
Мобильное приложение FRUktik
 (сжатие изображения, base64)
      │ HTTP POST (JSON)
      ▼
Сервер n8n (Webhook)
 (маршрутизация, обогащение запроса)
      │ HTTP POST (OpenRouter API)
      ▼
Mistral Large Vision
 (анализ фото, ответ с КБЖУ)
      │ JSON-ответ
      ▼
Сервер n8n (парсинг ответа)
      │ JSON-ответ клиенту
      ▼
Мобильное приложение FRUktik
 (отображение КБЖУ пользователю)
      │
      ▼
Supabase (сохранение записи в дневник)
```

#### 3.3.2 Мониторинг состояния сервера n8n

Для проверки доступности сервера n8n оператор может выполнить HTTP-запрос к встроенному эндпоинту проверки работоспособности:

```bash
curl -I http://<ВАШ_IP>:5678/healthz
```

Ожидаемый ответ: `HTTP/1.1 200 OK`

Для просмотра текущих выполнений рабочего процесса (Executions) в реальном времени:
1. Войдите в веб-интерфейс n8n.
2. Перейдите в раздел **«Executions»** в левом меню.
3. Здесь отображаются все входящие запросы, их статус (`Success` / `Error`) и время выполнения.

#### 3.3.3 Режим работы при отсутствии подключения к Интернету

Мобильное приложение поддерживает ограниченный автономный режим:
- Пользователь может просматривать ранее сохранённые записи дневника (кэш на устройстве).
- Анализ новых фотографий недоступен без подключения к сети.
- При восстановлении соединения приложение автоматически синхронизирует отложенные записи с Supabase (`DatabaseService`).

### 3.4 Проверка работоспособности системы

Для комплексной проверки работоспособности системы оператор должен выполнить следующие действия:

**Тест 1. Проверка n8n Webhook**

Отправьте тестовый POST-запрос к URL вебхука:

```bash
curl -X POST https://<ВАШ_ДОМЕН>:5678/webhook/<ИДЕНТИФИКАТОР> \
  -H "Content-Type: application/json" \
  -d '{"action": "parse", "query": "Тестовый запрос", "timestamp": "2026-01-01T00:00:00Z"}'
```

Ожидаемый результат: JSON-ответ с одним или несколькими полями (в зависимости от логики Workflow), HTTP-статус `200 OK`.

**Тест 2. Проверка подключения к Supabase**

В SQL Editor Supabase выполните:

```sql
SELECT COUNT(*) FROM diary_entries;
```

Ожидаемый результат: запрос выполняется без ошибок, возвращается число записей (0 для новой установки).

**Тест 3. Сквозной функциональный тест**

1. Запустите мобильное приложение на тестовом устройстве.
2. Зарегистрируйтесь или войдите в систему.
3. Сфотографируйте любое блюдо (или выберите фото из галереи).
4. Убедитесь, что приложение отображает данные КБЖУ в течение **не более 30 секунд**.
5. Убедитесь, что запись появилась в разделе «Дневник».
6. Проверьте в Supabase (SQL Editor), что запись добавлена в таблицу `diary_entries`.

## 4. СООБЩЕНИЯ ОПЕРАТОРУ

Настоящий раздел содержит перечень диагностических сообщений, которые могут возникнуть в журналах сервера n8n и в консоли отладки мобильного приложения, а также рекомендуемые действия оператора.

### 4.1 Сообщения об ошибках мобильного клиента

Сообщения отображаются в консоли отладки приложения (Flutter DevTools / `flutter logs`):

| Код / Сообщение | Причина | Действие оператора |
|-----------------|---------|-------------------|
| `⚠️ N8N Webhook URL is missing. Check AIConfig.` | URL вебхука n8n не задан в конфигурации приложения | Убедитесь, что в `ai_config.dart` указан корректный URL активированного вебхука n8n |
| `❌ n8n API Error 401` | Неверные учётные данные для аутентификации n8n | Проверьте настройки `N8N_BASIC_AUTH_USER` и `N8N_BASIC_AUTH_PASSWORD` в `docker-compose.yml` |
| `❌ n8n API Error 404` | Вебхук с указанным идентификатором не найден | Убедитесь, что Workflow в n8n **активирован** (статус «Active»). Проверьте корректность URL вебхука |
| `❌ n8n API Error 500` | Внутренняя ошибка на сервере n8n при выполнении Workflow | Проверьте раздел **Executions** в n8n — откройте упавшее выполнение и найдите узел с ошибкой. Проверьте журналы: `docker compose logs n8n` |
| `❌ Таймаут или ошибка сети: ...` | Сервер n8n недоступен или время ответа превысило 45 секунд | Проверьте доступность сервера: `curl -I http://<IP>:5678/healthz`. Перезапустите контейнер: `docker compose restart n8n` |
| `Error fetching entries: ...` | Ошибка при обращении к Supabase (чтение записей) | Проверьте правильность `supabaseUrl` и `supabaseAnonKey`. Проверьте наличие таблицы `diary_entries` и политик RLS |
| `Error adding entry: ...` | Ошибка при записи в Supabase | Проверьте политику RLS: пользователь должен быть аутентифицирован. Проверьте, что поля запроса соответствуют схеме таблицы |

### 4.2 Сообщения об ошибках сервера n8n

Сообщения доступны в разделе **Executions** веб-интерфейса n8n, а также в журналах Docker:

```bash
docker compose logs n8n --tail=100
```

| Сообщение / Симптом | Причина | Действие оператора |
|--------------------|---------|-------------------|
| Статус выполнения **Error** → узел «HTTP Request» (OpenRouter) | Неверный или истёкший API-ключ OpenRouter | Обновите API-ключ в настройках узла n8n. Проверьте баланс аккаунта на https://openrouter.ai |
| `Error: connect ECONNREFUSED` | n8n не может подключиться к внешнему сервису | Проверьте сетевые настройки сервера, правила брандмауэра, доступность внешних адресов |
| `Workflow is not active` | Рабочий процесс деактивирован | Активируйте Workflow через кнопку **«Activate»** в n8n |
| Контейнер постоянно перезапускается | Нехватка памяти или ошибка конфигурации | Проверьте логи: `docker compose logs n8n`. Убедитесь, что сервер соответствует минимальным требованиям (RAM ≥ 4 ГБ) |
| `ENOSPC: no space left on device` | Закончилось дисковое пространство | Освободите место на диске. Очистите старые образы Docker: `docker system prune` |

### 4.3 Сообщения Supabase

| Ситуация | Причина | Действие оператора |
|---------|---------|-------------------|
| `JWT expired` в логах клиента | Истёк срок действия токена аутентификации пользователя | Supabase обновляет токен автоматически; если ошибка повторяется — проверьте системное время на сервере (должно быть синхронизировано с NTP) |
| `new row violates row-level security policy` | Нарушение политики RLS при вставке записи | Убедитесь, что в запросе передаётся корректный `user_id` = `auth.uid()`. Проверьте политику RLS в Supabase |
| Таблица `diary_entries` не найдена | Миграция базы данных не была выполнена | Выполните SQL-скрипт создания таблицы из раздела 3.1.3 настоящего руководства |

### 4.4 Рекомендуемые действия при нештатных ситуациях

#### 4.4.1 Полный перезапуск серверной части

```bash
cd fruktik-n8n
docker compose restart
```

#### 4.4.2 Обновление образа n8n до последней версии

```bash
docker compose pull
docker compose up -d
```

#### 4.4.3 Резервное копирование данных n8n

```bash
# Создание резервной копии тома n8n
docker run --rm \
  -v fruktik-n8n_n8n_data:/data \
  -v $(pwd):/backup \
  alpine tar czf /backup/n8n_backup_$(date +%Y%m%d).tar.gz -C /data .
```

Резервную копию базы данных Supabase рекомендуется создавать с использованием встроенного инструмента в разделе **Settings → Database → Backups** панели управления Supabase.

#### 4.4.4 Восстановление данных n8n из резервной копии

```bash
docker compose down
docker run --rm \
  -v fruktik-n8n_n8n_data:/data \
  -v $(pwd):/backup \
  alpine tar xzf /backup/n8n_backup_YYYYMMDD.tar.gz -C /data
docker compose up -d
```
